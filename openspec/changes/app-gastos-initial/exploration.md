## Exploration: Mobills vs App-Gastos Balance Discrepancy

### Current State
Currently, `app-gastos` imports transactions via an Excel file generated by the `mobills-extractor` tool. 
In `app-gastos`, account balances are computed on-the-fly via a SQL query (`accounts.ts`) that sums all historical transactions (`income - expense + transfers`). There is no `initial_balance` field on the `accounts` table.
In `mobills-extractor/transform.ts`, transactions of `tipoMovimentacao === 5` (SaldoEsperado / Balance Adjustments) and `ignorada === true` are explicitly excluded from the Excel file.

### Affected Areas
- `tools/mobills-extractor/transform.ts` — Excludes `tipo === 5` which Mobills uses for balance adjustments or initial balances.
- `backend/src/controllers/accounts.ts` — Computes balance purely from transaction sums (no initial balance).
- `backend/src/controllers/importExport.ts` — Creates accounts on-the-fly with 0 initial balance.

### Why do the balances not match?
1. **Falta de Saldo Inicial (Initial Balances):** Como `app-gastos` suma todas las transacciones desde cero y no tiene un campo de "Saldo Inicial", cualquier saldo que tenías en Mobills antes de tu primera transacción (o cualquier saldo ajustado manualmente) no se refleja.
2. **Exclusión de Ajustes de Saldo (tipo 5):** Mobills permite hacer "Ajustes de Saldo". En la API de Mobills, esto viene como `tipoMovimentacao: 5` (SaldoEsperado). El archivo `transform.ts` descarta explícitamente estas filas (`if (tipo === 5) continue;`).
3. **Transacciones Ignoradas:** Si tenías transacciones marcadas como "ignoradas" en Mobills, el extractor también las omite. Si por alguna razón esas transacciones sumaban al saldo en tu vista de Mobills, aquí no lo harán.

### Is it better to import accounts first?
Importing accounts first **will not** automatically fix the balance issue, because `app-gastos` doesn't support setting an initial balance natively when creating an account (it always starts at 0). However, creating them first manually would allow you to add a manual transaction called "Saldo Inicial" for each account before running the mass import. 

### Approaches

1. **Approach A: Add "Initial Balance" feature to app-gastos (Recomendado a largo plazo)**
   - Modify the database schema to add `initial_balance` to `accounts`.
   - Update `getAccounts` to do `COALESCE(SUM(...), 0) + initial_balance`.
   - Update the UI and import logic to support it.
   - Pros: Solución arquitectónicamente correcta y robusta.
   - Cons: Requiere cambios en backend, frontend y base de datos.
   - Effort: Medium

2. **Approach B: Fix via manual "Saldo Inicial" transactions (Solución rápida)**
   - No code changes needed in `app-gastos`.
   - Import the data as is.
   - For each account, look at the difference between `app-gastos` and `Mobills`. Create a single manual Income or Expense transaction in `app-gastos` (e.g., dated before all other transactions) named "Ajuste de Saldo Inicial" to offset the difference.
   - Pros: Cero esfuerzo de desarrollo, lo puedes hacer hoy mismo.
   - Cons: Ensucia un poco el historial de transacciones con un "Ingreso" o "Gasto" de ajuste.
   - Effort: Low

3. **Approach C: Modify `transform.ts` to convert `tipo === 5` into Income/Expense**
   - Attempt to map `SaldoEsperado` entries into valid transactions in the Excel file.
   - Pros: Podría automatizar el ajuste al importar.
   - Cons: Muy propenso a errores porque `SaldoEsperado` suele ser un saldo absoluto (checkpoint) y no un delta relativo, por lo que requeriría calcular la diferencia en el script.
   - Effort: High

### Recommendation
Para solucionar tu problema hoy mismo y poder usar la app, te recomiendo el **Approach B**: luego de importar, crea una transacción manual de "Ingreso" o "Gasto" en cada cuenta por el valor exacto de la diferencia, llamándola "Ajuste de Saldo Inicial".
A nivel de código, recomiendo implementar el **Approach A** (agregar soporte para Saldo Inicial en la base de datos) ya que es un feature muy común en apps de finanzas.
